# คู่มือดูแลเว็บ

บันทึกสำหรับตอนกลับมาแก้เว็บนี้เอง — เว็บเป็น HTML/CSS/JS ล้วน แก้ไฟล์แล้วรีเฟรชเห็นผลทันที ไม่ต้อง build

หลักการเดียวกันหมดทุกส่วน: **หาบล็อกเดิมที่ใกล้เคียงที่สุด copy มาแล้วเปลี่ยนค่า** อย่าคิดโครงสร้างใหม่

## เพิ่มผลงาน (section Projects)

ส่วนนี้เป็น**รางเลื่อนแนวนอน** ไม่ใช่กริดแล้ว — หาคำว่า `<ul class="pc-track" id="projTrack">`
แล้ว copy `<li class="pc-item">` ใบที่ใกล้เคียงที่สุดมาทั้งก้อน เปลี่ยนค่าข้างใน

```html
<li class="pc-item">
  <article class="proj-card">
    <div class="proj-thumb">
      <img src="images/ชื่อไฟล์.jpg" width="1600" height="1000" loading="lazy" decoding="async"
        alt="ภาพหน้าจอของระบบ">
    </div>
    <h3>ชื่อผลงาน</h3>
    <p>อธิบายว่าทำอะไร ใช้อะไร ได้ผลยังไง</p>
    <ul class="proj-chips">
      <li><svg viewBox="0 0 1052 1052" aria-hidden="true" focusable="false"><use href="#logo-javascript" /></svg>JavaScript</li>
      <li>ชื่อเครื่องมือที่ไม่มีโลโก้</li>
    </ul>
    <div class="proj-foot">
      <div class="proj-links">
        <a href="ลิงก์เว็บจริง" target="_blank" rel="noopener noreferrer" aria-label="เปิดเว็บ ...">
          <svg width="15" height="15" aria-hidden="true" focusable="false"><use href="#icon-external" /></svg>
        </a>
        <a href="ลิงก์ repo" target="_blank" rel="noopener noreferrer" aria-label="ดูโค้ดบน GitHub">
          <svg width="15" height="15" aria-hidden="true" focusable="false"><use href="#icon-github" /></svg>
        </a>
      </div>
      <a class="btn btn-outline btn-sm proj-more" href="ลิงก์" target="_blank" rel="noopener noreferrer">
        อ่านเพิ่มเติม
        <svg width="13" height="13" aria-hidden="true" focusable="false"><use href="#icon-external" /></svg>
      </a>
    </div>
  </article>
</li>
```

ไม่ต้องแตะปุ่มลูกศรหรือ JS — `script.js` นับการ์ดเองจาก DOM

**กฎของส่วนนี้**

| กฎ | เหตุผล |
|---|---|
| **`viewBox` ของชิปโลโก้ต้องลอกจาก `<symbol>` ต้นทาง ห้ามเดา** | symbol แต่ละตัวมี viewBox ไม่เท่ากัน · firebase คือ `0 0 600 600` ไม่ใช่ `0 0 24 24` · ใส่ผิดแล้วรูปถูกครอปเหลือมุมเดียว ไม่ error ให้เห็น · ดูค่าที่ถูกได้จากที่ส่วน Skills เรียกใช้อยู่ |
| **ยังไม่มีภาพหน้าจอ ให้ใช้ไทล์โลโก้ `class="proj-thumb is-mark"`** | ข้างในเป็น `<svg><use href="#logo-xxx" /></svg>` ของเทคโนโลยีหลัก + `<span>` ป้ายหมวด เช่น Data Pipeline · อ่านเป็นงานออกแบบ ไม่ใช่ช่องที่ลืมใส่รูป · พอได้ภาพจริงแล้วแทนทั้งบล็อกด้วย `<div class="proj-thumb"><img ...></div>` ธรรมดา |
| **อย่าใส่รูปกิจกรรมแทนภาพหน้าจอระบบ** | การ์ดจะโกหกว่าเป็นหน้าจอของแอป |
| **อยากแคปหน้า dashboard ของงาน pipeline ใหม่ ให้เปิด Docker Desktop ก่อนแล้วรัน `docker compose up -d` ในโฟลเดอร์ repo นั้น** | ทั้ง 3 งาน (cost-of-living, crypto, football) หน้าเว็บเป็นแค่เปลือก ตัวเลขอยู่ใน PostgreSQL ที่ Airflow เติมให้ ถ้าไม่เปิด Docker จะได้หน้าเปล่า · **cost-of-living กับ football ชน port 5433 และ 8080 ห้ามเปิดพร้อมกัน** (crypto ใช้ 5435/8081/8002 ไม่ชนใคร) · dashboard อยู่ที่ cost `:8001` · crypto `:8002` · football `:8501` |
| **cost-of-living ไม่ต้องรัน backfill 2 ชั่วโมง ใช้ snapshot สำเร็จรูปแทน** | `bash scripts/restore_snapshot.sh` ได้ CPI 3.3 ล้านแถวใน 1-3 นาที · ถ้าโหลดตรงจาก GitHub Release ไม่ได้ (504) ให้ดึงผ่าน API แทน: `curl -L -H "Accept: application/octet-stream" -o snap.tar.gz https://api.github.com/repos/Catboyz-45/cost-of-living-pipeline/releases/assets/605581112` แล้วส่งไฟล์เป็น argument: `bash scripts/restore_snapshot.sh snap.tar.gz` |
| **ถ้า Flask ของ football ขึ้น "ยังไม่มีข้อมูลใน PostgreSQL" ทั้งที่ตารางมีแถวอยู่ ให้ดู log ก่อนโทษ DAG** | `docker logs football-pipeline-web-1` · สาเหตุที่เจอคือรหัสผ่านใน `.env` ไม่ตรงกับที่ค้างใน volume เก่า (Postgres ตั้งรหัสตอน init ครั้งแรกครั้งเดียว) แก้ด้วย `docker exec football-pipeline-football-db-1 psql -U football -d football -c "ALTER USER football WITH PASSWORD '...';"` แล้ว restart web · **`q()` ใน `web/app.py` ดัก `psycopg2.Error` ทิ้ง** หน้าเว็บเลยขึ้นว่า "ไม่มีข้อมูล" แทนที่จะ error ให้เห็น |
| **ShabuQ ยังเป็นไทล์โลโก้ เพราะเป็นแอป Flutter ไม่ใช่เว็บ** | repo รองรับ `flutter build web` (มีโฟลเดอร์ `web/`) และ Flutter SDK อยู่ที่ `C:\Development\FlutterSDK` แต่แอปเปิดมาเจอหน้าล็อกอินก่อน และ Firebase เป็นโปรเจกต์จริงบนคลาวด์ (`ftf3-4c575`) **ห้ามสมัครบัญชีหรือล็อกอินเพื่อแคปรูป** · ถ้าอยากได้ภาพหน้าจอจริงให้เจ้าของรันบน emulator แล้วแคปเอง |
| **คำอธิบายถูกตัดที่ 4 บรรทัดด้วย `-webkit-line-clamp`** | ให้การ์ดทุกใบสูงใกล้กัน · เขียนยาวได้แต่คนจะเห็นแค่ 4 บรรทัด |
| **ปุ่มลูกศรซ่อนด้วย `opacity: 0` ต้องมี `pointer-events: none` คู่เสมอ** | ปุ่มที่โปร่งใสยังกินคลิกอยู่ · ถ้าลืม ปุ่มที่มองไม่เห็นจะไปบังปุ่มในการ์ดข้างใต้ และจะหาสาเหตุไม่เจอเพราะไม่มีอะไรให้เห็น |
| **ปุ่มลูกศรต้องโผล่ทั้งตอน `:hover` และ `:focus-within` ของ `.pc-wrap`** | คนที่ใช้คีย์บอร์ดกด Tab เข้ามาจะโฟกัสปุ่มที่มองไม่เห็น ถ้าเปิดด้วย hover อย่างเดียว |
| **อย่าเพิ่มตัวบอกว่า "เลื่อนได้" กลับเข้าไปอีก** | ตอนนี้มี **2 อย่างต่ออุปกรณ์ และไม่ซ้ำกันเลย** — เดสก์ท็อป: การ์ดโผล่ขอบ + ลูกศรลอยตอน hover · มือถือ: การ์ดโผล่ขอบ + จุด · เคยมีแถบเลื่อน ม่านจาง และข้อความ "ปัดเพื่อดูเพิ่ม" ด้วย รวมเป็น 4 อย่างที่สื่อเรื่องเดียวกัน รกและซ้ำซ้อน |
| **ตำแหน่งลูกศร: แนวตั้งกึ่งกลาง ภาพ แนวนอนชิดขอบจอ 16px** | **ห้ามใช้ `top: 50%`** — การ์ดสูง 520px จะได้ 244px ซึ่งตกกลางย่อหน้าคำอธิบาย อ่านเป็นปุ่มลอยมาทับข้อความ · ค่าที่ถูกคือ `calc(6px + 14px + (var(--pc-card-w) - 2px - 28px) * 10 / 16 / 2)` ≈ 111px (padding ราง + padding การ์ด + ครึ่งความสูงภาพ 16/10) · **`--pc-card-w` ประกาศไว้ที่ `.pc-wrap` และ `.pc-item` ก็ใช้ตัวเดียวกัน** แก้ความกว้างการ์ดที่เดียว ปุ่มขยับตามเอง · แนวนอนใช้ `left/right: 16px` เฉย ๆ ไม่ต้องคิดจากคอลัมน์ 1100px เพราะรางเป็น full-bleed ปุ่มจึงไปนั่งบนการ์ดที่โผล่มาครึ่งใบริมจอพอดี (เจ้าของเลือกแบบนี้เองหลังเทียบ 3 แบบจากหน้าจริง) |
| **เคยถามแล้วว่าจะเอาจุดมาโชว์บนเดสก์ท็อปด้วยไหม คำตอบคือ "ไม่เอา"** | เจ้าของสั่งให้เพิ่มแล้วเปลี่ยนใจภายในนาทีเดียว · เดสก์ท็อปคงเหลือ 2 อย่างตามเดิม — การ์ดโผล่ขอบ + ลูกศร · **ไม่ต้องเสนอเรื่องนี้อีก** |
| **จุดกับลูกศรใช้เงื่อนไข media query ตัวเดียวกัน ห้ามแยกจากกัน** | `@media (hover: none), (max-width: 768px)` ซ่อนลูกศรและโชว์จุดในบล็อกเดียว · ถ้าแยกเมื่อไหร่จะมีช่วงความกว้างที่โผล่พร้อมกันทั้งคู่ หรือหายไปทั้งคู่ |
| **ไม่ต้องเติมจุดเองตอนเพิ่มการ์ด** | `script.js` สร้างจุดจากจำนวน `.pc-item` ที่มีจริง และดึง `aria-label` จาก `<h3>` ของการ์ด |
| **ถ้าแก้ `padding-inline` ของ `.pc-track` ต้องแก้ทั้ง 2 ที่** | ค่าปกติ `max(40px, calc((100vw - 1100px)/2 + 40px))` กับค่าที่ `@media (max-width: 960px)` เป็น 24px · ตัวเลขต้องตรงกับ `.container` ไม่งั้นการ์ดใบแรกจะไม่ตรงขอบกับหัวข้อ |

## เพิ่มกิจกรรม / ดูงาน (section Activities)

คนละส่วนกับ Projects — หา `<div class="act-grid">` แล้วเพิ่ม:

```html
<article class="act-item reveal">
  <div class="act-thumb">
    <img src="images/ชื่อไฟล์.jpg" width="2048" height="1368" loading="lazy" decoding="async"
      alt="คำอธิบายรูปสั้น ๆ">
  </div>
  <div class="act-body">
    <p class="act-kind">ดูงาน</p>
    <h3>ชื่อที่ไป</h3>
    <p>ได้เรียนรู้อะไร สั้น ๆ 2 บรรทัด</p>
  </div>
</article>
```

**การ์ดนี้ตั้งใจให้ดู "เงียบ" กว่าการ์ดโปรเจกต์** — รูปเล็กอยู่ข้าง ไม่มีชิป ไม่มีปุ่ม พื้นโปร่งไม่มีเงา
**อย่าเอาการ์ดทรงเดียวกับโปรเจกต์มาใช้** ต่อให้อยู่คนละ section คนก็ยังกวาดตารวมเป็นกองเดียว
ซึ่งเป็นปัญหาเดิมตอนที่สองอย่างนี้อยู่ใต้หัวข้อ `Projects & Activities` เดียวกัน

## แก้ประวัติการศึกษา (section Education)

เส้นเวลาที่เส้นทอง "วาด" ลงมาตามการเลื่อนหน้า รายการใหม่สุดอยู่บน ก๊อปก้อนนี้ไปวางใน `<div class="timeline">`

```html
<article class="tl-item">
  <div class="tl-year">2027<small>– 2029</small></div>
  <span class="tl-dot" aria-hidden="true"></span>
  <div class="tl-card">
    <span class="tl-now">กำลังศึกษา</span>   <!-- ใส่เฉพาะที่ยังเรียนอยู่ จบแล้วลบบรรทัดนี้ -->
    <h3>ระดับการศึกษา</h3>
    <p class="tl-place">ชื่อสถาบัน</p>
    <ul class="tl-meta">
      <li>คณะ / แผนการเรียน</li>
      <li>สาขา</li>
      <li>เกรดเฉลี่ย 0.00</li>
    </ul>
  </div>
</article>
```

| เรื่อง | รายละเอียด |
|---|---|
| ไม่ต้องใส่คลาส `reveal` | ส่วนนี้มีอนิเมชันของตัวเอง ใส่ซ้อนแล้วจะจางสองชั้น |
| ไม่ต้องแก้ `script.js` ตอนเพิ่มรายการ | สคริปต์หา `.tl-item` ทุกอันเอง ความยาวเส้นคิดจากความสูงของ `.timeline` |
| คลาส `tl-live` กับ `is-on` ไม่มีใน HTML | `script.js` เป็นคนเติม — **ห้ามลบ rule ที่ขึ้นต้นด้วย `.timeline.tl-live`** ถึงจะค้นใน HTML ไม่เจอ |
| หน้าตาตั้งต้นใน CSS คือ "สว่างครบ" | สถานะจางอยู่ใต้ `.tl-live` เท่านั้น ถ้าสคริปต์ไม่ทำงานหรือเครื่องตั้งลดการเคลื่อนไหวไว้ เนื้อหาจะเห็นครบทันที · ถ้าจะแก้สไตล์ตอนจาง แก้ใต้ `.tl-live` อย่าย้ายขึ้นไปไว้ที่ rule หลัก |
| จุดที่เส้นวิ่งไปถึง | ค่า `TL_TRIGGER = 0.62` ใน `script.js` = 62% ของความสูงจอนับจากบน เพิ่มเลขถ้าอยากให้สว่างเร็วขึ้น |
| ตำแหน่งราง `left: 170px` | มาจากคอลัมน์ปี 140px + ครึ่งคอลัมน์จุด 31px − 1px ถ้าแก้ `grid-template-columns` ของ `.tl-item` ต้องแก้เลขนี้ตาม |

**ฟอนต์ของส่วนนี้** ใช้ชุดเดียวกับส่วนอื่นของเว็บ: หัวข้อ `--font-display` · ชิปกับป้าย `--font-body` · ที่เหลือสืบทอดจาก `body`
เลขปีใส่ `font-variant-numeric: lining-nums` ไว้ให้ตัวเลขสูงเท่ากันทุกตัว ถ้าเอาออกเลขจะกลับเป็นแบบสูงต่ำไม่เท่ากัน

## เพิ่มใบรับรอง (section Certificates)

ส่วนนี้เป็น Coverflow 3D — ใบกลางหันตรง ใบข้างเอียงลึกเข้าไป กดใบกลางแล้วขยายเต็มจอ
ก๊อปก้อนนี้ไปวางต่อท้ายใน `<div class="cert-stage">` **ไม่ต้องแก้ `script.js`** จุดบอกตำแหน่งกับลำดับในกล่องขยายนับจากจำนวน `<figure>` เอง

```html
<figure class="cert-item">
  <button type="button" class="cert-shot">
    <img src="images/ชื่อไฟล์.jpg" width="2481" height="1890" loading="lazy" decoding="async" class="cert-img" alt="ใบรับรอง X (ระดับ) จาก Y">
  </button>
  <figcaption class="cert-info">
    <h3>ชื่อใบรับรอง</h3>
    <p class="cert-meta"><span class="cert-level">Basic</span><span class="cert-issuer">Issued by ผู้ออก</span><span class="cert-date">ปี</span></p>
  </figcaption>
</figure>
```

| เรื่อง | รายละเอียด |
|---|---|
| ระดับ Intermediate ขึ้นไป | ใช้ `<span class="cert-level is-mid">` จะได้ชิปพื้นทอง |
| `width` / `height` ของ `<img>` | ใส่ขนาดจริงของไฟล์ · รูปถูกครอบให้เป็นสัดส่วน 2481:1890 เสมอ ใบที่สัดส่วนต่างจากนี้จะโดนตัดขอบ |
| ไม่ต้องใส่จุดคั่นหน้าปี | CSS ใส่ `·` ให้เองหน้า `.cert-date` |
| ชื่อใต้ใบกลางมาจากไหน | `script.js` ก๊อปเนื้อใน `<figcaption>` ของใบกลางไปวางใน `.cert-cap` · แก้ชื่อที่ `<figcaption>` ที่เดียว |
| คลาส `is-live` กับ `is-active` ไม่มีใน HTML | `script.js` เป็นคนเติม — **ห้ามลบ rule ที่ขึ้นต้นด้วย `.cert-flow.is-live`** |
| ถ้าสคริปต์ไม่ทำงาน | ส่วนนี้กลายเป็นกริด 3 คอลัมน์ธรรมดาที่มีชื่ออยู่ใต้รูป ยังเห็นครบทุกใบ |
| ขนาดใบกลาง | `--cert-w` ใน `.cert-flow` (จอกว้าง 50% · จอ ≤768px 78%) ความสูงเวทีคิดจากค่านี้เอง |
| ระยะและมุมของใบข้าง | ค่าคงที่บนสุดของบล็อก Certificates ใน `script.js`: `CF_SHIFT` `CF_DEPTH` `CF_ANGLE` `CF_VISIBLE` |
| **อย่าใช้ attribute `data-open` ในส่วนนี้** | โค้ดของ Workshop ผูกทุก `[data-open]` ในหน้าไว้เปิดกล่องรายละเอียดเอกสาร |

## เพิ่มเอกสาร PDF (section Workshop)

วางไฟล์ใน `pdf/` แล้วเพิ่มการ์ดใหม่ใน `<div class="doc-grid">`:


## แก้เนื้อหาในกล่องรายละเอียด Workshop

คลิกปุ่ม **รายละเอียด** บนการ์ดแล้วกล่องจะเด้งขึ้นกลางจอ · เนื้อหาอยู่ใน [`../index.html`](../index.html)
เป็น `<dialog class="doc-modal" id="dm-1">` ถึง `dm-4` วางต่อจาก `.doc-grid` ในส่วน Workshop

โครงของแต่ละกล่องคงที่ 4 หัวข้อ แก้ข้อความในนั้นได้ตรง ๆ:

| หัวข้อ | ใส่อะไร |
|---|---|
| **โจทย์** | ปัญหาของระบบเดิมที่เอกสารเล่มนั้นตั้งไว้ · หนึ่งย่อหน้า |
| **สิ่งที่ทำ** | สิ่งที่ลงมือทำจริงในบทบาทนั้น · เป็นข้อ ๆ |
| **สิ่งที่ได้จากงานนี้** | สิ่งที่ได้เรียนรู้ ไม่ใช่สรุปว่าทำอะไร · เป็นข้อ ๆ |
| **สิ่งที่อยู่ในเล่ม / เครื่องมือที่ใช้** | ชิปสั้น ๆ ใน `.dm-tags` |

**กฎของส่วนนี้**

| กฎ | เหตุผล |
|---|---|
| เขียนจากในเอกสารจริงเท่านั้น ห้ามเดา | ถ้ามีคนเปิด PDF ตามแล้วไม่ตรง จะเสียความน่าเชื่อถือทันที · ดึงข้อความออกมาอ่านได้ด้วย `pdftotext -enc UTF-8 -f 1 -l 12 pdf/<ไฟล์>.pdf out.txt` |
| ปุ่มก่อนหน้า/ถัดไปเป็นวงกลม ต้องแก้ `data-open` ทั้งสองฝั่งเมื่อเพิ่มหรือลบกล่อง | `dm-4` ชี้กลับไป `dm-1` ถ้าเพิ่มกล่องที่ 5 แล้วลืมแก้ วงจะขาด |
| ตัวเลข `1 / 4` ใน `.dm-count` เขียนตายตัวใน HTML | เพิ่มกล่องเมื่อไหร่ต้องไล่แก้ทุกใบ |
| ห้ามตั้ง `display` ให้ `.doc-modal` (ตั้งได้เฉพาะ `.doc-modal[open]`) | เบราว์เซอร์ใช้ `display: none` ซ่อนกล่องตอนปิด ถ้าไปทับ กล่องจะโผล่ค้างอยู่กลางหน้า |
| `.doc-modal` ต้องมี `margin: auto` | reset ของเว็บตั้ง `margin: 0` ให้ทุกอย่าง ซึ่งไปทับค่าที่เบราว์เซอร์ใช้จัดกล่องให้อยู่กลางจอ ถ้าลบออก กล่องจะไปกองมุมซ้ายบน |
| ในกล่องมีชิปสองระดับ ห้ามทำให้หน้าตาเหมือนกัน | **บทบาท** (`.dm-role`) เป็นพื้นกรมท่าทึบตัวหนังสือขาว เพราะเป็นข้อความหลักของกล่อง · **รายละเอียด** (`.dm-tags span`) เป็นชิปจางสีกลาง · ของเดิมใช้พื้น `--elevated` เหมือนกันทั้งคู่ ต่างแค่เอาขอบทองมาแปะที่ `.dm-role` ซึ่งขอบอุ่นบนพื้นเทาอมฟ้าตีกันเอง และยังอ่านเป็นชิประดับเดียวกันอยู่ดี |
| ห้ามใช้สีเน้นแบบ**จาง ๆ** เป็นพื้นชิป | สีจางทับพื้นการ์ดแล้วดันพื้นให้เปลี่ยนไป ตัวหนังสือจะตกเกณฑ์ · `.dm-role` เคยวัดได้ **4.00:1** ด้วยวิธีนี้ · พื้นทึบกรมท่าได้ 13.67:1 |

> เนื้อหาในกล่องอยู่ใน HTML ตรง ๆ ไม่ได้สร้างด้วย JS
> ต่อให้ JS ไม่ทำงาน Google กับโปรแกรมอ่านหน้าจอก็ยังเห็นข้อความครบ (แค่ปุ่มจะถูกซ่อนไปเพราะกดแล้วไม่เกิดอะไร)

## เพิ่มโลโก้ (แถบ Logo Loop / กริดไทล์)

โหลดไฟล์จาก [thesvg.org](https://thesvg.org) (MIT) — URL ตรงคือ

```
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/public/icons/<ชื่อ>/default.svg
```

> **ถ้า thesvg ไม่มีโลโก้ที่ต้องการ** ลอง [simple-icons](https://simpleicons.org) (CC0) ก่อน
> ถ้ายังไม่มีอีกค่อยไป [icons8](https://icons8.com) — **แต่ icons8 แบบใช้ฟรีบังคับให้มีลิงก์กลับ**
> ตอนนี้เครดิตอยู่ที่ footer แล้ว (`.footer-credit`) ถ้าเพิ่มไอคอนจากแหล่งใหม่ที่ต้องให้เครดิต ต้องไปเติมชื่อตรงนั้นด้วย

**1)** เพิ่ม `<symbol>` เข้าไปใน sprite ที่หัว `index.html` โดยเอา **แท็ก `<svg>` ชั้นนอกออก** แล้ว

- ยก attribute ที่อยู่บนแท็กนั้นขึ้นไปไว้บน `<symbol>` ด้วย โดยเฉพาะ `fill` — บางโลโก้ (เช่น Docker) ใส่สีไว้ตรงนี้ที่เดียว ถ้าทิ้งไปโลโก้จะกลายเป็นสีดำ
- ถ้าไฟล์ประกาศ `id` ข้างใน (gradient, clipPath) **ต้องเติม prefix ให้ไม่ซ้ำกับตัวอื่น** แล้วตามไปแก้ `url(#...)` กับ `href="#..."` ทุกจุด หลายไฟล์ตั้งชื่อว่า `id="a"` เหมือนกันหมด

**2)** เรียกใช้ — จะใส่ในแถบวิ่งข้างบน หรือในกริดไทล์ก็ได้ ใช้ `<symbol>` ตัวเดียวกันซ้ำได้เลย

```html
<!-- แถบวิ่งข้างบน (อย่าลืมเพิ่มชื่อในรายการ .sr-only ด้วย) -->
<div class="logo-loop-item">
  <svg data-logo="ชื่อ" viewBox="0 0 กว้าง สูง"><use href="#logo-ชื่อ" /></svg>
</div>

<!-- ไทล์ในกริด (ใส่ในหมวดที่ต้องการ) -->
<div class="tech-tile">
  <svg data-logo="ชื่อ" viewBox="0 0 กว้าง สูง" aria-hidden="true"><use href="#logo-ชื่อ" /></svg>
  <span>ชื่อที่จะให้แสดง</span>
</div>
```

> **เช็คสีก่อนเสมอ** — `default.svg` ของบางแบรนด์เป็นภาพ**สีขาวล้วน** (ทำมาสำหรับพื้นมืด) จะหายไปเลยบนไทล์ขาว
> MySQL เป็นแบบนี้ ต้องเปลี่ยน `fill` เป็นสีแบรนด์เอง · ถ้าไม่มีตัวสีให้ใช้ `mono.svg` แล้วกำหนดสีเอง
> แต่ดูก่อนว่ามีตัวหนังสือชื่อแบรนด์ติดมาในภาพไหม จะได้ไม่ซ้ำกับ `<span>` ใต้โลโก้

> **ถ้า `default.svg` เป็นภาพซับซ้อน (mask + blur) ให้มองหาตัวเส้นเดียวแทน** — Gemini ของ thesvg
> เป็นก้อนแสงเบลอ 7 ชั้นซ้อนใต้ mask และประกาศ id ข้างใน 8 ตัว ย่อลงมา 44x44 แล้วเละ
> เปลี่ยนไปใช้ตัว path เดียวของ [simple-icons](https://simpleicons.org) (CC0 ไม่ต้องให้เครดิต) แล้วกำหนดสีแบรนด์เอง
> โลโก้ AI ที่เพิ่มเข้ามาใช้วิธีนี้ 2 ใบคือ Gemini กับ GitHub Copilot ที่เหลือมาจาก thesvg

> `viewBox` ของ `<svg>` ตัวนี้ต้องขึ้นต้นด้วย **`0 0`** เสมอ ใส่แค่ความกว้าง-สูงจาก viewBox ต้นฉบับ
> (ส่วน `<symbol>` เก็บ viewBox เดิมไว้ทั้งอัน) — ถ้าใส่ค่าที่ไม่ได้เริ่มที่ `0 0` ทั้งสองที่ โลโก้จะเหลือแค่เศษมุมเดียว

**3)** ถ้าโลโก้ทรงสูง (สูงกว่ากว้าง) มันจะดูเล็กกว่าโลโก้ทรงจัตุรัสที่อยู่ข้าง ๆ ทั้งที่สูงเท่ากัน ต้องชดเชยใน [`../style.css`](../style.css)

- **แถบวิ่ง** เพิ่ม `height` ที่กลุ่ม `.logo-loop-item svg[data-logo="..."]` ได้เลย
- **ไทล์** ต้องใช้ `transform: scale()` ที่กลุ่ม `.tech-tile svg[data-logo="..."]` **ห้ามเพิ่ม `height`** เพราะกล่องถูกล็อกเป็นจัตุรัส 44×44 ไว้ให้ป้ายชื่อทุกใบอยู่ระดับเดียวกัน

จำนวนชุดที่ต้องโคลนคำนวณเองใน [`../script.js`](../script.js) ไม่ต้องแก้

## หน้า Home (เอาออกแล้ว)

**ตอนนี้ไม่มีหน้า Home** — เจ้าของสั่งเอาออก หน้าเว็บเริ่มที่ส่วน About เลย
โลโก้ navbar กับลิงก์ "↑ Top" ใน footer ชี้ `#about` · `<h1>` กลับไปเป็น `sr-only` ไว้ก่อน `#about`

| สิ่งที่ต้องรู้ถ้าจะแก้ส่วนบนของหน้า | เหตุผล |
|---|---|
| `.about-hero` มี `padding-top` ของตัวเอง (160px · มือถือ 130px) | About เป็นส่วนแรก navbar ลอยทับขอบบนอยู่ 67px ถ้าใช้ padding ของ `.section` เฉย ๆ หัวข้อบนมือถือห่างจาก navbar แค่ 3px |
| หน้าต้องมี `<h1>` 1 ตัวเสมอ | ถ้าลบ `<h1 class="sr-only">` ทิ้ง โครงหัวข้อจะเริ่มที่ h2 โปรแกรมอ่านหน้าจอและ Google หาหัวเรื่องของหน้าไม่เจอ |

**ถ้าจะทำหน้า Home กลับมา** ไฟล์เต็มชุดสุดท้ายที่มีหน้า Home (พร้อมอนิเมชัน 3 อย่าง) สำรองไว้ที่ scratchpad ชื่อ `*.before-removehome`
บทเรียนที่ได้จากสองรอบที่ทำ:

- **พื้นหลังดาว WebGL (Galaxy จาก React Bits) กระตุกบนเครื่องจริง** — shader คิดดาวราว 36 ดวงต่อ pixel ต่อให้จำกัดความละเอียดแล้วก็ยังหนัก · โค้ดเก็บอยู่ที่ `galaxy.js.removed` (ต้องคงประกาศลิขสิทธิ์ MIT + Commons Clause)
- อนิเมชันต้องขยับแค่ `transform` กับ `opacity` · แยกชื่อได้ทีละคำ ห้ามทีละตัวอักษร (สระ/วรรณยุกต์ไทยหลุด)
- บล็อก `prefers-reduced-motion` ต้องสั่ง `animation: none` ตรง ๆ และระวังน้ำหนัก selector ของ `:nth-child()`
- ความสูงเต็มจอใช้ `100svh` ตามหลัง `100vh` · ห้ามเพิ่มลิงก์ "Home" ในเมนู (เมนูมือถือเต็มที่ 6 ลิงก์)

## ปุ่ม CV บน navbar

มีสองปุ่มชี้ไฟล์ `pdf/CV.pdf` เดียวกัน: **View CV** (ปุ่มขอบ เปิดอ่านในแท็บใหม่) กับ **Download CV** (ปุ่มทึบ บันทึกลงเครื่อง)
เปลี่ยนไฟล์ CV ให้แทนที่ `pdf/CV.pdf` ชื่อเดิม ไม่ต้องแก้ HTML · ชื่อไฟล์ตอนดาวน์โหลดตั้งที่ `download="..."`

ที่ว่างใน navbar ไม่พอให้ข้อความเต็มทุกความกว้าง จึงย่อตามจอ (วัดช่องว่างจริงทุกขนาดแล้ว แคบสุด 21px):

| ความกว้างจอ | View CV | Download CV |
|---|---|---|
| 1200px ขึ้นไป | ไอคอน + ข้อความ | ไอคอน + ข้อความ |
| 961-1199px (เมนูยังเรียงเต็มแถว) | **ไอคอนรูปตาอย่างเดียว** | ไอคอน + ข้อความ |
| 769-960px (เมนูเป็นแฮมเบอร์เกอร์แล้ว) | ไอคอน + ข้อความ | ไอคอน + ข้อความ |
| **768px ลงไป (มือถือ)** | **รวมเป็นปุ่ม "CV" ปุ่มเดียว** กดแล้วแผ่นเลือกเลื่อนขึ้นจากล่างจอ มีปุ่ม View CV กับ Download CV แบบข้อความเต็ม | ← |

> ถ้าเพิ่มลิงก์ในเมนูหรือเปลี่ยนชื่อปุ่ม ต้องวัดใหม่ที่ 961px และ 320px สองจุดนี้ชิดที่สุด
> ปุ่มที่เหลือแต่ไอคอนยังมี `aria-label` และ `title` บอกชื่อปุ่มอยู่ ห้ามลบ

**แผ่นเลือก CV บนมือถือ** คือ `<dialog class="cv-sheet" id="cvSheet">` ที่อยู่ถัดจากเมนูมือถือใน `index.html`

| เรื่อง | รายละเอียด |
|---|---|
| **เปลี่ยนไฟล์ CV แล้วต้องแก้ขนาดไฟล์** | บรรทัด `<p class="cv-sheet-meta">ไฟล์ PDF · 268 KB</p>` พิมพ์ไว้เอง ไม่ได้อ่านจากไฟล์ |
| ลิงก์ CV มี 4 จุด | สองปุ่มใน navbar + สองปุ่มในแผ่นเลือก ถ้าเปลี่ยนชื่อไฟล์หรือชื่อตอนดาวน์โหลด (`download="..."`) ต้องแก้ให้ครบ |
| คลาส `has-cv-sheet` ไม่มีใน HTML | `script.js` เติมให้ `<html>` เมื่อเบราว์เซอร์เปิด dialog ได้ — CSS ใช้คลาสนี้ซ่อนสองปุ่มเดิมแล้วโชว์ปุ่ม CV **ห้ามลบ rule ที่ขึ้นต้นด้วย `.has-cv-sheet`** |
| ถ้าสคริปต์ไม่ทำงาน | ไม่มี `has-cv-sheet` สองปุ่มเดิมยังอยู่บนมือถือและกดได้ (เหลือไอคอนตากับคำว่า CV แบบเดิม) กฎย่อปุ่มที่ ≤768px / ≤480px จึงต้องเก็บไว้ |
| `padding` ของแผ่นอยู่ที่ `.cv-sheet-inner` ไม่ใช่ที่ `<dialog>` | สคริปต์ปิดแผ่นเมื่อกดโดนตัว dialog ตรง ๆ ซึ่งหมายถึงฉากหลัง ถ้าย้าย padding ไปไว้ที่ dialog กดขอบในของแผ่นจะปิดไปด้วย |

## แก้ส่วน Contact

**ลำดับความสำคัญคือหัวใจของส่วนนี้ ไม่ใช่การตกแต่ง**

|---|---|---|
| 1 | Gmail | ปุ่มขาวใหญ่ `.contact-cta` — ปุ่มเดียวของทั้งส่วน เป็นช่องทางที่ HR ใช้จริง |

เพิ่มช่องทางใหม่: ก๊อปก้อนนี้ไปวางใน `<div class="contact-social">`

```html
<a href="https://..." class="contact-chip" target="_blank" rel="noopener noreferrer">

  <span>ชื่อบัญชี</span>
</a>
```

| กฎ | เหตุผล |
|---|---|
| **โลโก้แบรนด์ต้องนั่งบนแผ่นขาว `.ci-badge`** | สีแบรนด์วางบนพื้นกรมท่าตรง ๆ ได้ IG 2.49 · FB 2.55 · GitHub 1.66 : 1 ตกเกณฑ์ 3:1 ทั้งหมด |

| ไอคอนในปุ่มหลักต้องเป็นเส้น `currentColor` ห้ามใช้โลโก้ Gmail สีจริง | ปุ่มเปลี่ยนพื้นเป็นสีทองตอน hover โลโก้สี่สีบนพื้นทองจะดูมั่ว |
| `.contact-copy` ต้องมี `.contact-copy[hidden] { display: none }` | `display: flex` ที่ตั้งไว้จะไปทับ `[hidden]` ของเบราว์เซอร์ ปุ่มจะโผล่ค้างแม้ JS สั่งซ่อนไว้ |
| ข้อความในชิปต้องตัดกลางคำได้ (`overflow-wrap: anywhere`) | `github.com/nanthapat3751` ตัดคำเองไม่ได้ ที่จอ 320px เคยดันทั้งหน้าให้เลื่อนแนวนอนได้ |
| ปุ่มอีเมลย่อตัวหนังสือตามจอที่ ≤768px (`clamp()`) | อีเมลยาวบรรทัดเดียว ถ้าใช้ขนาดจอคอมจะกว้างเกินจอมือถือ · เปลี่ยนอีเมลเป็นอันที่ยาวกว่านี้ต้องเช็กที่ 320px ใหม่ |
| แสงสีทองหลังคำชวนเป็น `::before` ของ `.contact-section` | `script.js` ย้ายตามเมาส์ด้วย `--glow-x` / `--glow-y` · ห้ามเอา `overflow: hidden` ออกจาก `.contact-section` ไม่งั้นแสงล้นออกนอกส่วน |

> **ปุ่มคัดลอกอีเมลซ่อนไว้ใน HTML แล้วให้ JS เปิด** — `navigator.clipboard` ใช้ไม่ได้ถ้าเปิดไฟล์แบบ `file://`
> หรือเสิร์ฟผ่าน http ธรรมดา ถ้าโชว์ไว้เฉย ๆ จะกลายเป็นปุ่มกดแล้วไม่เกิดอะไร
> **เวลาทดสอบต้องคลิกจริง** การเรียก `el.click()` ด้วย JS ไม่นับเป็น user activation เบราว์เซอร์จะปฏิเสธเสมอ

## แก้สี / ฟอนต์

เว็บนี้เป็น **ธีมสว่าง** (ครีม-ทอง-กรมท่า) แก้ที่ตัวแปรบนสุดของ [`../style.css`](../style.css) ที่เดียว **อย่า hardcode สีลงใน rule**

```css
:root {
  --bg: #E4EBF5;        /* พื้นหน้าเว็บ */
  --surface: #FFFFFF;   /* พื้นการ์ด · แถบสลับ */
  --elevated: #D8E2F0;  /* ชิป · เมนูมือถือ · navbar ตอนเลื่อนแล้ว */
  --border: #C6D5EA;    /* ขอบการ์ด */
  --text: #0F1B42;      /* ตัวหนังสือหลัก */
  --muted: #4F6089;     /* ตัวหนังสือรอง */
  --dim: #9AA5C0;       /* ใช้บนพื้นกรมท่าของ Contact ที่เดียว */
  --accent: #C9960C;    /* ทอง — ใช้กับเส้น ขอบ พื้น เท่านั้น */
  --accent-text: #7B5C05;     /* ทองเข้มสำหรับใช้เป็น 'ตัวหนังสือ' */
  --accent2: #1a2a5e;   /* กรมท่า — พื้นปุ่มทึบ · ส่วน Contact · footer */
  --on-accent: #FFFFFF;       /* ตัวหนังสือบนพื้น --accent2 */
  --on-accent-light: #1a2a5e; /* ตัวหนังสือบนพื้นทอง --accent */
  --on-accent-muted: rgba(255,255,255,0.72); /* ตัวหนังสือรองบนพื้น --accent2 */
  ...
}
```

**เว็บนี้มีพื้นสองโลก** — ส่วนใหญ่เป็นพื้นสว่าง แต่ **Contact กับ footer เป็นกรมท่า**
สีที่ใช้ได้ในโลกหนึ่งมักใช้ไม่ได้ในอีกโลก ทุกครั้งที่แตะสีตัวหนังสือต้องถามก่อนว่าจุดนั้นอยู่บนพื้นอะไร

| กฎ | เหตุผล |
|---|---|
| ทอง `--accent` ห้ามใช้เป็น **ตัวหนังสือ** บนพื้นสว่าง ใช้ `--accent-text` แทน | ทองบนครีมได้แค่ **2.2–2.7:1** · เคยหลุดไปโผล่ที่ `.tech-tier-label` `.dot` `.section-title em` `.mobile-menu a:hover` `.proj-tag:hover` มาแล้วพร้อมกัน 5 จุด |

| `--accent2` เป็น **พื้น** เท่านั้น ห้ามเอาไปเป็นสีตัวหนังสือบนพื้นสว่าง | มันเข้มพอ ๆ กับ `--text` ใช้แทนกันได้ก็จริง แต่จะสับสนว่าอันไหนทำหน้าที่อะไร |
| **ห้ามลบ token ทิ้งโดยไม่ไล่ดูว่ามีใครเรียกใช้อยู่** | เคยเขียนทับ `:root` ทั้งบล็อก `--accent-text` หายไปเงียบ ๆ ทั้งที่มี 7 rule เรียกใช้ · CSS ไม่ error สีแค่ตกกลับไปเป็นสีที่สืบทอดมา มองไม่ออกถ้าไม่เทียบของเดิม |
| **สถานะ `:hover` ต้องตรวจคอนทราสต์ด้วย** | ตัวตรวจปกติวัดแต่สถานะปกติ · วิธีที่ใช้ได้คือ**โคลนกฎ `:hover` เป็นกฎที่ยิงด้วยคลาสธรรมดา** แล้วใส่คลาสให้ element (ทา property ทีละตัวลง `el.style` ไม่ได้ ค่าที่เป็น `var()` ไม่ยอมลง · `CSS.forcePseudoState` ก็ไม่ได้ หน้าจอเปลี่ยนแต่ `getComputedStyle` ยังคืนค่าสถานะปกติ) |
| ตัวหนังสือสีขาวโปร่ง (`rgba(255,255,255,...)`) ต้องใช้ `--on-accent-muted` | ค่าโปร่งทำให้คอนทราสต์จริงต่ำกว่าที่ตาเห็นมาก จุดที่คับสุดคือตัวหนังสือบนชิปหรือการ์ดโปร่งในส่วน Contact เพราะมีพื้นขาวจางทับอีกชั้น |

> **แถบสลับพื้นหลัง** `.section-alt` เป็นไล่สีที่**เริ่มและจบด้วย `--bg`** แล้วค่อยเป็น `--surface` เต็มที่ระยะ 130px
> ห้ามเปลี่ยนเป็นสีทึบ เพราะ section 4 ใน 7 อันเตี้ยกว่าความสูงจอ จอจึงเหลือที่ให้แถบข้างเคียงโผล่เสมอ
> ถ้าเป็นสีทึบจะเห็นเป็นเส้นคมพาดกลางจอ

> **ตรวจคอนทราสต์ต้องคิดค่าโปร่งใสด้วย** — ตัวตรวจรุ่นแรกอ่านแค่ค่า RGB ทิ้ง alpha ไป
> เลยรายงานว่า `rgba(255,255,255,0.55)` ผ่านสบาย ทั้งที่ของจริงได้ 4.08:1 (ตก)
> ตัวตรวจต้องผสมสีตัวหนังสือกับพื้นตามค่า alpha ก่อนคำนวณ และต้องผสมพื้นโปร่งที่ซ้อนกันหลายชั้นด้วย
> (เช่น ตัวหนังสือบน `.contact-chip` ซึ่งเป็นชิปโปร่งที่วางบนพื้น `--accent2` อีกที)

## กฎที่ต้องรักษาไว้เสมอ

| กฎ | เหตุผล |
|---|---|
| **แก้ `style.css` หรือ `script.js` แล้วต้องเปลี่ยนเลข `?v=` ใน `index.html`** (ท้าย `<link>` และ `<script>`) ก่อนอัปขึ้น GitHub | เบราว์เซอร์จำไฟล์ CSS/JS เก่าไว้ แต่ HTML มักโหลดใหม่ ได้ของผสมที่ไม่เข้ากัน · เคยเกิดจริง: HTML ใหม่ใส่ `width/height` ให้รูปโปรไฟล์ แต่ CSS เก่าในแคชไม่มี `img { height: auto }` รูปจึงสูง 1433px ยืดเป็นเส้น · ใช้วันที่เป็นเลขรุ่นก็พอ เช่น `20260917` |
| ทุก `<img>` ต้องมี `alt` | คนใช้ screen reader และตอนรูปโหลดไม่ขึ้น |
| ทุก `target="_blank"` ต้องมี `rel="noopener noreferrer"` | ความปลอดภัย |
| path ต้องเป็น `images/...` `pdf/...` **ห้ามมี `../`** | ถ้าพลาดรูปจะแตกทั้งเว็บตอน deploy |
| **ชื่อไฟล์ในโฟลเดอร์ `images/` และ `pdf/` ต้องเป็นอังกฤษ ตัวเล็ก คั่นด้วย `-`** | ชื่อไทยพอเข้า URL กลายเป็น `%E0%B8%A3...` ยาว 60+ ตัว เคยหล่นหายตอนอัปขึ้น GitHub จนลิงก์ 404 มาแล้ว |
| ห้ามมีเว้นวรรคในชื่อไฟล์ | กลายเป็น `%20` ในลิงก์ พิมพ์ตามยาก และบางเครื่องมือตัดชื่อตรงช่องว่าง |
| ใส่คลาส `reveal` ถ้าอยากให้ค่อย ๆ ปรากฏตอนเลื่อน | เพิ่ม `reveal-delay` / `reveal-delay-2` เพื่อหน่วงเป็นลำดับ |
| section ใหม่ควรมี `id` และลิงก์ทั้งใน `.nav-links` และ `.mobile-menu` | ไม่งั้นเข้าไม่ถึงจากเมนู ต้องเลื่อนหาเอง (Workshop ตั้งใจไม่ใส่ เพราะเมนูจะยาวเกินไป) |
| `@media (max-width: ...)` ต้องเรียง **กว้างไปแคบ** เสมอ | specificity เท่ากัน ตัวที่อยู่ทีหลังชนะ ถ้าเรียงสลับ ค่าที่แคบกว่าจะไม่ทำงานเลย |
| **จุดเปลี่ยนเลย์เอาต์ใช้ได้แค่ 3 ค่า: `960px` · `768px` · `480px`** (กับ `1199px` ที่ใช้เฉพาะ navbar) | เคยมีถึง 9 ค่าปนกัน (1040 / 820 / 640 / 600 / 560 ...) บางช่วงจอได้ของผสมจากสองชุด · ถ้าของใหม่ไม่ลงตัวกับ 3 ค่านี้ ลองใช้ `clamp()` หรือ `repeat(auto-fit, minmax(...))` ก่อนจะเพิ่มค่าที่สี่ |
| ปุ่มและลิงก์บนจอ ≤768px ต้องมีพื้นที่กดอย่างน้อย **44px** | นิ้วกดไม่แม่นเท่าเมาส์ · กฎรวมอยู่ในบล็อก "จอสัมผัส" ท้าย `style.css` ปุ่มแบบใหม่ต้องไปเพิ่มที่นั่น |
| ตัวหนังสือบนจอ ≤768px ห้ามเล็กกว่า **12.5px** | ชื่อใต้ไทล์โลโก้เคยเป็น 11px อ่านยากบนมือถือ |
| **แก้ media query ด้วยสคริปต์หรือค้นหา-แทนที่ทั้งก้อน ต้องเทียบรายชื่อ selector ก่อน/หลัง** | เคยย้ายบล็อกแล้วกฎ `.pc-dots` 5 ตัวที่อยู่ระหว่างสองบล็อกหายไปเงียบ ๆ CSS ไม่ error แค่จุดโผล่มาบนเดสก์ท็อป |

> ถ้าเพิ่มลิงก์เมนู ต้องขยาย `max-height` ของ `.mobile-menu.open` ใน [`../style.css`](../style.css) ด้วย (ตอนนี้ตั้งไว้สำหรับ 6 ลิงก์)
> (ลิงก์ละ ~58px — สูตรอยู่ในคอมเมนต์ตรงนั้น) ไม่งั้นลิงก์ท้าย ๆ จะโดน `overflow: hidden` ตัดหายและกดไม่ได้

- **ย่อรูปในโฟลเดอร์ `images/`** — รูปใหญ่เกินที่แสดงจริงหลายเท่า (ใบรับรอง 6 ใบ ~630 KB/ใบ · `INET.jpg` 1.1 MB · `Zahira.jpg` 1.0 MB · `myproflie.png` 1.5 MB) · ใบรับรองกดขยายเต็มจอได้แล้ว จึงควรย่อเหลือกว้างราว **1600px** ไม่ใช่เล็กกว่านั้น ส่วนรูปกิจกรรมย่อเหลือ 1200px ได้
- **รูปของการ์ด JavaScript (Basic) เป็นใบ Python** — ไฟล์ `javascript_basic certificate.jpg` เป็นไฟล์เดียวกับ `python_basic certificate.jpg` ทุกไบต์ ต้องเอารูปใบ JavaScript จริงมาวางทับ หรือเอาการ์ดนี้ออก
- **ชื่อไฟล์ใบรับรอง 5 ไฟล์มีเว้นวรรค** (เช่น `java_basic certificate.jpg`) ผิดกฎตั้งชื่อไฟล์ข้างบน เปลี่ยนชื่อพร้อมแก้ `src` ตอนย่อรูปได้เลย
- **CSS 14 rule ที่ยังไม่มีใครใช้** — ส่วนใหญ่มาร์กอัปถูกคอมเมนต์ทิ้งไว้ใน `index.html` (`.section-title` 6 รูปแบบ · `.proj-tag` + `:hover` · `.tag-blue` `.tag-green` `.tag-purple` · `.proj-year` · `.pc-header` · `.about-text strong`) บวก **`.section-open`** ที่เพิ่งว่างลงตอนถอดออกจาก About · ยังไม่ลบเพราะถ้าเอามาร์กอัปกลับมาใช้จะได้ไม่ต้องเขียนใหม่ ถ้าแน่ใจว่าไม่ใช้แล้วค่อยลบทั้งคู่พร้อมกัน
  > **เวลาไล่หา rule ที่ไม่มีใครใช้ ระวังคลาสที่ JS เป็นคนใส่** — `.navbar.scrolled` `.mobile-menu.open` `#backToTop.show` `.reveal.visible` `.ripple-effect` `.contact-copy[hidden]` `.timeline.tl-live` `.tl-item.is-on` `.cert-flow.is-live` `.cert-item.is-active` `.has-cv-sheet` ไม่มีอยู่ใน HTML เลย แต่ทั้งหมดใช้งานอยู่จริง **ห้ามลบ**
