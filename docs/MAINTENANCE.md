# คู่มือดูแลเว็บ

บันทึกสำหรับตอนกลับมาแก้เว็บนี้เอง — เว็บเป็น HTML/CSS/JS ล้วน แก้ไฟล์แล้วรีเฟรชเห็นผลทันที ไม่ต้อง build

หลักการเดียวกันหมดทุกส่วน: **หาบล็อกเดิมที่ใกล้เคียงที่สุด copy มาแล้วเปลี่ยนค่า** อย่าคิดโครงสร้างใหม่

```html
  <h3>ชื่อผลงาน</h3>
  <div class="project-img">
    <img src="images/ชื่อไฟล์.jpg" alt="คำอธิบายรูปสั้น ๆ">
  </div>
  <p>อธิบายว่าทำอะไร ใช้อะไร ได้ผลยังไง</p>
  <div class="proj-stack">
    <span>เครื่องมือ 1</span><span>เครื่องมือ 2</span>
  </div>
</div>
```

## เพิ่มเอกสาร PDF (section Workshop)

วางไฟล์ใน `pdf/` แล้วเพิ่มการ์ดใหม่ใน `<div class="doc-grid">`:

```html
<article class="doc-card reveal">
  <div class="doc-card-head">
    <span class="doc-icon"><svg width="20" height="20" aria-hidden="true" focusable="false"><use href="#icon-doc" /></svg></span>
    <span class="doc-kind">รายงานวิเคราะห์ระบบ</span>
  </div>
  <h3 class="doc-title">ชื่อเอกสาร</h3>
  <p class="doc-meta">00 หน้า · PDF · 2567</p>
  <div class="doc-actions">
    <a href="pdf/file-name.pdf" target="_blank" rel="noopener noreferrer" class="btn btn-sm">ดูเอกสาร</a>
    <a href="pdf/file-name.pdf" download="ชื่อไทยที่จะให้เซฟลงเครื่อง.pdf" class="btn btn-outline btn-sm">ดาวน์โหลด</a>
  </div>
</article>
```

**ไอคอนกับชนิดเอกสารต้องไปด้วยกัน**

| ชนิด | `doc-kind` | ไอคอน |
|---|---|---|
| รายงาน / เอกสารเป็นเล่ม | `รายงานวิเคราะห์ระบบ` | `#icon-doc` |
| สไลด์นำเสนอ | `สไลด์นำเสนอ` | `#icon-slides` |

> **จำนวนหน้าใส่ให้ตรงกับไฟล์จริง** — เปิด PDF ดูเลขหน้าสุดท้ายก็ได้
> ตัวเลขนี้สำคัญกว่าที่คิด รายงาน 74–91 หน้าบอกน้ำหนักงานได้ชัดกว่าคำว่า "PDF" เฉย ๆ มาก

> **ชื่อไฟล์เป็นอังกฤษ แต่คนโหลดได้ชื่อไทย** — `href` ใช้ชื่ออังกฤษเพื่อให้ URL ทนทาน
> ส่วน `download="..."` กำหนดชื่อที่จะเซฟลงเครื่องได้ ใส่ชื่อไทยตรงนั้นแทน
> ได้ทั้งสองอย่าง: ลิงก์ไม่พัง และไฟล์ที่โหลดไปยังอ่านรู้เรื่อง

การ์ดยืดความสูงให้เท่ากันเองภายในแถวเดียวกัน และแถวปุ่มถูกดันไปชิดล่างด้วย `margin-top: auto`
ชื่อเอกสารยาวกี่บรรทัดปุ่มก็ยังตรงแนวกับใบอื่น

## แก้เนื้อหาในกล่องรายละเอียด Workshop

คลิกปุ่ม **รายละเอียด** บนการ์ดแล้วกล่องจะเด้งขึ้นกลางจอ · เนื้อหาอยู่ใน [`../index.html`](../index.html)
เป็น `<dialog class="doc-modal" id="dm-1">` ถึง `dm-4` วางต่อจาก `.doc-grid` ในส่วน Workshop

โครงของแต่ละกล่องคงที่ 4 หัวข้อ แก้ข้อความในนั้นได้ตรง ๆ:

| หัวข้อ | ใส่อะไร |
|---|---|
| **โจทย์** | ปัญหาของระบบเดิมที่เอกสารเล่มนั้นตั้งไว้ · หนึ่งย่อหน้า |
| **สิ่งที่ทำ** | สิ่งที่ลงมือทำจริงในบทบาทนั้น · เป็นข้อ ๆ |
| **สิ่งที่ได้จากงานนี้** | สิ่งที่ได้เรียนรู้ ไม่ใช่สรุปว่าทำอะไร · เป็นข้อ ๆ |
| **สิ่งที่อยู่ในเล่ม / เครื่องมือที่ใช้** | ชิปสั้น ๆ ใน `.dm-tags` |

**กฎของส่วนนี้**

| กฎ | เหตุผล |
|---|---|
| เขียนจากในเอกสารจริงเท่านั้น ห้ามเดา | ถ้ามีคนเปิด PDF ตามแล้วไม่ตรง จะเสียความน่าเชื่อถือทันที · ดึงข้อความออกมาอ่านได้ด้วย `pdftotext -enc UTF-8 -f 1 -l 12 pdf/<ไฟล์>.pdf out.txt` |
| ปุ่มก่อนหน้า/ถัดไปเป็นวงกลม ต้องแก้ `data-open` ทั้งสองฝั่งเมื่อเพิ่มหรือลบกล่อง | `dm-4` ชี้กลับไป `dm-1` ถ้าเพิ่มกล่องที่ 5 แล้วลืมแก้ วงจะขาด |
| ตัวเลข `1 / 4` ใน `.dm-count` เขียนตายตัวใน HTML | เพิ่มกล่องเมื่อไหร่ต้องไล่แก้ทุกใบ |
| ห้ามตั้ง `display` ให้ `.doc-modal` (ตั้งได้เฉพาะ `.doc-modal[open]`) | เบราว์เซอร์ใช้ `display: none` ซ่อนกล่องตอนปิด ถ้าไปทับ กล่องจะโผล่ค้างอยู่กลางหน้า |
| `.doc-modal` ต้องมี `margin: auto` | reset ของเว็บตั้ง `margin: 0` ให้ทุกอย่าง ซึ่งไปทับค่าที่เบราว์เซอร์ใช้จัดกล่องให้อยู่กลางจอ ถ้าลบออก กล่องจะไปกองมุมซ้ายบน |
| ในกล่องมีชิปสองระดับ ห้ามทำให้หน้าตาเหมือนกัน | **บทบาท** (`.dm-role`) เป็นพื้นกรมท่าทึบตัวหนังสือขาว เพราะเป็นข้อความหลักของกล่อง · **รายละเอียด** (`.dm-tags span`) เป็นชิปจางสีกลาง · ของเดิมใช้พื้น `--elevated` เหมือนกันทั้งคู่ ต่างแค่เอาขอบทองมาแปะที่ `.dm-role` ซึ่งขอบอุ่นบนพื้นเทาอมฟ้าตีกันเอง และยังอ่านเป็นชิประดับเดียวกันอยู่ดี |
| ห้ามใช้สีเน้นแบบ**จาง ๆ** เป็นพื้นชิป | สีจางทับพื้นการ์ดแล้วดันพื้นให้เปลี่ยนไป ตัวหนังสือจะตกเกณฑ์ · `.dm-role` เคยวัดได้ **4.00:1** ด้วยวิธีนี้ · พื้นทึบกรมท่าได้ 13.67:1 |

> เนื้อหาในกล่องอยู่ใน HTML ตรง ๆ ไม่ได้สร้างด้วย JS
> ต่อให้ JS ไม่ทำงาน Google กับโปรแกรมอ่านหน้าจอก็ยังเห็นข้อความครบ (แค่ปุ่มจะถูกซ่อนไปเพราะกดแล้วไม่เกิดอะไร)

## เพิ่มโลโก้ (แถบ Logo Loop / กริดไทล์)

โหลดไฟล์จาก [thesvg.org](https://thesvg.org) (MIT) — URL ตรงคือ

```
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/public/icons/<ชื่อ>/default.svg
```

> **ถ้า thesvg ไม่มีโลโก้ที่ต้องการ** ลอง [simple-icons](https://simpleicons.org) (CC0) ก่อน
> ถ้ายังไม่มีอีกค่อยไป [icons8](https://icons8.com) — **แต่ icons8 แบบใช้ฟรีบังคับให้มีลิงก์กลับ**
> ตอนนี้เครดิตอยู่ที่ footer แล้ว (`.footer-credit`) ถ้าเพิ่มไอคอนจากแหล่งใหม่ที่ต้องให้เครดิต ต้องไปเติมชื่อตรงนั้นด้วย

**1)** เพิ่ม `<symbol>` เข้าไปใน sprite ที่หัว `index.html` โดยเอา **แท็ก `<svg>` ชั้นนอกออก** แล้ว

- ยก attribute ที่อยู่บนแท็กนั้นขึ้นไปไว้บน `<symbol>` ด้วย โดยเฉพาะ `fill` — บางโลโก้ (เช่น Docker) ใส่สีไว้ตรงนี้ที่เดียว ถ้าทิ้งไปโลโก้จะกลายเป็นสีดำ
- ถ้าไฟล์ประกาศ `id` ข้างใน (gradient, clipPath) **ต้องเติม prefix ให้ไม่ซ้ำกับตัวอื่น** แล้วตามไปแก้ `url(#...)` กับ `href="#..."` ทุกจุด หลายไฟล์ตั้งชื่อว่า `id="a"` เหมือนกันหมด

**2)** เรียกใช้ — จะใส่ในแถบวิ่งข้างบน หรือในกริดไทล์ก็ได้ ใช้ `<symbol>` ตัวเดียวกันซ้ำได้เลย

```html
<!-- แถบวิ่งข้างบน (อย่าลืมเพิ่มชื่อในรายการ .sr-only ด้วย) -->
<div class="logo-loop-item">
  <svg data-logo="ชื่อ" viewBox="0 0 กว้าง สูง"><use href="#logo-ชื่อ" /></svg>
</div>

<!-- ไทล์ในกริด (ใส่ในหมวดที่ต้องการ) -->
<div class="tech-tile">
  <svg data-logo="ชื่อ" viewBox="0 0 กว้าง สูง" aria-hidden="true"><use href="#logo-ชื่อ" /></svg>
  <span>ชื่อที่จะให้แสดง</span>
</div>
```

> **เช็คสีก่อนเสมอ** — `default.svg` ของบางแบรนด์เป็นภาพ**สีขาวล้วน** (ทำมาสำหรับพื้นมืด) จะหายไปเลยบนไทล์ขาว
> MySQL เป็นแบบนี้ ต้องเปลี่ยน `fill` เป็นสีแบรนด์เอง · ถ้าไม่มีตัวสีให้ใช้ `mono.svg` แล้วกำหนดสีเอง
> แต่ดูก่อนว่ามีตัวหนังสือชื่อแบรนด์ติดมาในภาพไหม จะได้ไม่ซ้ำกับ `<span>` ใต้โลโก้

> **ถ้า `default.svg` เป็นภาพซับซ้อน (mask + blur) ให้มองหาตัวเส้นเดียวแทน** — Gemini ของ thesvg
> เป็นก้อนแสงเบลอ 7 ชั้นซ้อนใต้ mask และประกาศ id ข้างใน 8 ตัว ย่อลงมา 44x44 แล้วเละ
> เปลี่ยนไปใช้ตัว path เดียวของ [simple-icons](https://simpleicons.org) (CC0 ไม่ต้องให้เครดิต) แล้วกำหนดสีแบรนด์เอง
> โลโก้ AI ที่เพิ่มเข้ามาใช้วิธีนี้ 2 ใบคือ Gemini กับ GitHub Copilot ที่เหลือมาจาก thesvg

> `viewBox` ของ `<svg>` ตัวนี้ต้องขึ้นต้นด้วย **`0 0`** เสมอ ใส่แค่ความกว้าง-สูงจาก viewBox ต้นฉบับ
> (ส่วน `<symbol>` เก็บ viewBox เดิมไว้ทั้งอัน) — ถ้าใส่ค่าที่ไม่ได้เริ่มที่ `0 0` ทั้งสองที่ โลโก้จะเหลือแค่เศษมุมเดียว

**3)** ถ้าโลโก้ทรงสูง (สูงกว่ากว้าง) มันจะดูเล็กกว่าโลโก้ทรงจัตุรัสที่อยู่ข้าง ๆ ทั้งที่สูงเท่ากัน ต้องชดเชยใน [`../style.css`](../style.css)

- **แถบวิ่ง** เพิ่ม `height` ที่กลุ่ม `.logo-loop-item svg[data-logo="..."]` ได้เลย
- **ไทล์** ต้องใช้ `transform: scale()` ที่กลุ่ม `.tech-tile svg[data-logo="..."]` **ห้ามเพิ่ม `height`** เพราะกล่องถูกล็อกเป็นจัตุรัส 44×44 ไว้ให้ป้ายชื่อทุกใบอยู่ระดับเดียวกัน

จำนวนชุดที่ต้องโคลนคำนวณเองใน [`../script.js`](../script.js) ไม่ต้องแก้

## หน้า Home (เอาออกแล้ว)

**ตอนนี้ไม่มีหน้า Home** — เจ้าของสั่งเอาออก หน้าเว็บเริ่มที่ส่วน About เลย
โลโก้ navbar กับลิงก์ "↑ Top" ใน footer ชี้ `#about` · `<h1>` กลับไปเป็น `sr-only` ไว้ก่อน `#about`

| สิ่งที่ต้องรู้ถ้าจะแก้ส่วนบนของหน้า | เหตุผล |
|---|---|
| `.about-hero` มี `padding-top` ของตัวเอง (160px · มือถือ 130px) | About เป็นส่วนแรก navbar ลอยทับขอบบนอยู่ 67px ถ้าใช้ padding ของ `.section` เฉย ๆ หัวข้อบนมือถือห่างจาก navbar แค่ 3px |
| หน้าต้องมี `<h1>` 1 ตัวเสมอ | ถ้าลบ `<h1 class="sr-only">` ทิ้ง โครงหัวข้อจะเริ่มที่ h2 โปรแกรมอ่านหน้าจอและ Google หาหัวเรื่องของหน้าไม่เจอ |

**ถ้าจะทำหน้า Home กลับมา** ไฟล์เต็มชุดสุดท้ายที่มีหน้า Home (พร้อมอนิเมชัน 3 อย่าง) สำรองไว้ที่ scratchpad ชื่อ `*.before-removehome`
บทเรียนที่ได้จากสองรอบที่ทำ:

- **พื้นหลังดาว WebGL (Galaxy จาก React Bits) กระตุกบนเครื่องจริง** — shader คิดดาวราว 36 ดวงต่อ pixel ต่อให้จำกัดความละเอียดแล้วก็ยังหนัก · โค้ดเก็บอยู่ที่ `galaxy.js.removed` (ต้องคงประกาศลิขสิทธิ์ MIT + Commons Clause)
- อนิเมชันต้องขยับแค่ `transform` กับ `opacity` · แยกชื่อได้ทีละคำ ห้ามทีละตัวอักษร (สระ/วรรณยุกต์ไทยหลุด)
- บล็อก `prefers-reduced-motion` ต้องสั่ง `animation: none` ตรง ๆ และระวังน้ำหนัก selector ของ `:nth-child()`
- ความสูงเต็มจอใช้ `100svh` ตามหลัง `100vh` · ห้ามเพิ่มลิงก์ "Home" ในเมนู (เมนูมือถือเต็มที่ 6 ลิงก์)

## ปุ่ม CV บน navbar

มีสองปุ่มชี้ไฟล์ `pdf/CV.pdf` เดียวกัน: **View CV** (ปุ่มขอบ เปิดอ่านในแท็บใหม่) กับ **Download CV** (ปุ่มทึบ บันทึกลงเครื่อง)
เปลี่ยนไฟล์ CV ให้แทนที่ `pdf/CV.pdf` ชื่อเดิม ไม่ต้องแก้ HTML · ชื่อไฟล์ตอนดาวน์โหลดตั้งที่ `download="..."`

ที่ว่างใน navbar ไม่พอให้ข้อความเต็มทุกความกว้าง จึงย่อตามจอ (วัดช่องว่างจริงทุกขนาดแล้ว แคบสุด 21px):

| ความกว้างจอ | View CV | Download CV |
|---|---|---|
| 1200px ขึ้นไป | ไอคอน + ข้อความ | ไอคอน + ข้อความ |
| 961-1199px (เมนูยังเรียงเต็มแถว) | **ไอคอนรูปตาอย่างเดียว** | ไอคอน + ข้อความ |
| 601-960px (เมนูเป็นแฮมเบอร์เกอร์แล้ว) | ไอคอน + ข้อความ | ไอคอน + ข้อความ |
| 481-600px | ไอคอนรูปตาอย่างเดียว | ไอคอน + ข้อความ |
| 480px ลงไป | ไอคอนรูปตาอย่างเดียว | **"⬇ CV"** |

> ถ้าเพิ่มลิงก์ในเมนูหรือเปลี่ยนชื่อปุ่ม ต้องวัดใหม่ที่ 961px และ 320px สองจุดนี้ชิดที่สุด
> ปุ่มที่เหลือแต่ไอคอนยังมี `aria-label` และ `title` บอกชื่อปุ่มอยู่ ห้ามลบ

## แก้สี / ฟอนต์

เว็บนี้เป็น **ธีมสว่าง** (ครีม-ทอง-กรมท่า) แก้ที่ตัวแปรบนสุดของ [`../style.css`](../style.css) ที่เดียว **อย่า hardcode สีลงใน rule**

```css
:root {
  --bg: #E4EBF5;        /* พื้นหน้าเว็บ */
  --surface: #FFFFFF;   /* พื้นการ์ด · แถบสลับ */
  --elevated: #D8E2F0;  /* ชิป · เมนูมือถือ · navbar ตอนเลื่อนแล้ว */
  --border: #C6D5EA;    /* ขอบการ์ด */
  --text: #0F1B42;      /* ตัวหนังสือหลัก */
  --muted: #4F6089;     /* ตัวหนังสือรอง */
  --dim: #9AA5C0;       /* ใช้บนพื้นกรมท่าของ Contact ที่เดียว */
  --accent: #C9960C;    /* ทอง — ใช้กับเส้น ขอบ พื้น เท่านั้น */
  --accent-text: #7B5C05;     /* ทองเข้มสำหรับใช้เป็น 'ตัวหนังสือ' */
  --accent2: #1a2a5e;   /* กรมท่า — พื้นปุ่มทึบ · ส่วน Contact · footer */
  --on-accent: #FFFFFF;       /* ตัวหนังสือบนพื้น --accent2 */
  --on-accent-light: #1a2a5e; /* ตัวหนังสือบนพื้นทอง --accent */
  --on-accent-muted: rgba(255,255,255,0.72); /* ตัวหนังสือรองบนพื้น --accent2 */
  ...
}
```

**เว็บนี้มีพื้นสองโลก** — ส่วนใหญ่เป็นพื้นสว่าง แต่ **Contact กับ footer เป็นกรมท่า**
สีที่ใช้ได้ในโลกหนึ่งมักใช้ไม่ได้ในอีกโลก ทุกครั้งที่แตะสีตัวหนังสือต้องถามก่อนว่าจุดนั้นอยู่บนพื้นอะไร

| กฎ | เหตุผล |
|---|---|
| ทอง `--accent` ห้ามใช้เป็น **ตัวหนังสือ** บนพื้นสว่าง ใช้ `--accent-text` แทน | ทองบนครีมได้แค่ **2.2–2.7:1** · เคยหลุดไปโผล่ที่ `.tech-tier-label` `.dot` `.section-title em` `.mobile-menu a:hover` `.proj-tag:hover` มาแล้วพร้อมกัน 5 จุด |
| แต่บนพื้นกรมท่าให้ใช้ `--accent` ตามเดิม (`.footer .dot` · `.back-top:hover` · `.footer-credit a:hover`) | ทิศทางกลับกัน ทองเข้มบนกรมท่าเหลือ 2.20:1 ส่วนทองสว่างได้ 5.17:1 |
| `--dim` ใช้บนพื้นกรมท่าเท่านั้น | บนการ์ดขาวมันได้ 2.50:1 · `.cert-date` กับ `.proj-year` เคยใช้ผิดมาแล้ว |
| `--muted` ต้องวัดกับ **ชิป `--elevated`** ไม่ใช่พื้นหน้าเว็บ | ชิปเข้มกว่าพื้น ค่าเดิม `#556793` ผ่านบนพื้น (4.67) แต่ตกบนชิป (4.36) — วัดผิดที่มาตั้งแต่ ISSUE-43 |
| ปุ่มที่พื้น hover เป็นทอง ต้องใช้ `--on-accent-light` (กรมท่า) เป็นสีตัวหนังสือ | ขาวบนทองได้แค่ 2.67:1 ซึ่งเป็นค่าที่ธีมเดิมใช้อยู่จริง ๆ |
| ปลายไล่สีของปุ่มตอน hover ต้อง**สว่างกว่า**ทอง ไม่ใช่เข้มกว่า | ปลายเข้ม (`#b56a32` / `#a37a0a`) ทำให้ตัวหนังสือกรมท่าเหลือ 3.3–3.5:1 · ใช้ `#E3B23C` แล้วจุดที่แย่ที่สุดของไล่สีได้ 5.17:1 |
| เงาเป็นฐานกรมท่า `rgba(15,27,66,...)` ไม่ใช่ดำ | เงาดำบนพื้นสว่างดูเปื้อน |
| โลโก้ใหม่ต้องเช็กว่าเข้มพอบนพื้น `--surface` (>= 3:1) | โลโก้ที่ทำมาสำหรับพื้นมืดจะหายไปบนไทล์ขาว · MySQL PHP DBeaver Spyder เคยต้องสลับกลับไปกลับมาแล้วรอบหนึ่ง |
| `--accent2` เป็น **พื้น** เท่านั้น ห้ามเอาไปเป็นสีตัวหนังสือบนพื้นสว่าง | มันเข้มพอ ๆ กับ `--text` ใช้แทนกันได้ก็จริง แต่จะสับสนว่าอันไหนทำหน้าที่อะไร |
| **ห้ามลบ token ทิ้งโดยไม่ไล่ดูว่ามีใครเรียกใช้อยู่** | เคยเขียนทับ `:root` ทั้งบล็อก `--accent-text` หายไปเงียบ ๆ ทั้งที่มี 7 rule เรียกใช้ · CSS ไม่ error สีแค่ตกกลับไปเป็นสีที่สืบทอดมา มองไม่ออกถ้าไม่เทียบของเดิม |
| **สถานะ `:hover` ต้องตรวจคอนทราสต์ด้วย** | ตัวตรวจปกติวัดแต่สถานะปกติ · วิธีที่ใช้ได้คือ**โคลนกฎ `:hover` เป็นกฎที่ยิงด้วยคลาสธรรมดา** แล้วใส่คลาสให้ element (ทา property ทีละตัวลง `el.style` ไม่ได้ ค่าที่เป็น `var()` ไม่ยอมลง · `CSS.forcePseudoState` ก็ไม่ได้ หน้าจอเปลี่ยนแต่ `getComputedStyle` ยังคืนค่าสถานะปกติ) |
| ตัวหนังสือสีขาวโปร่ง (`rgba(255,255,255,...)`) ต้องใช้ `--on-accent-muted` | ค่าโปร่งทำให้คอนทราสต์จริงต่ำกว่าที่ตาเห็นมาก จุดที่คับสุดคือ `.ci-label` เพราะการ์ดติดต่อมีพื้นขาวจางทับอีกชั้น |

> **แถบสลับพื้นหลัง** `.section-alt` เป็นไล่สีที่**เริ่มและจบด้วย `--bg`** แล้วค่อยเป็น `--surface` เต็มที่ระยะ 130px
> ห้ามเปลี่ยนเป็นสีทึบ เพราะ section 4 ใน 7 อันเตี้ยกว่าความสูงจอ จอจึงเหลือที่ให้แถบข้างเคียงโผล่เสมอ
> ถ้าเป็นสีทึบจะเห็นเป็นเส้นคมพาดกลางจอ

> **ตรวจคอนทราสต์ต้องคิดค่าโปร่งใสด้วย** — ตัวตรวจรุ่นแรกอ่านแค่ค่า RGB ทิ้ง alpha ไป
> เลยรายงานว่า `rgba(255,255,255,0.55)` ผ่านสบาย ทั้งที่ของจริงได้ 4.08:1 (ตก)
> ตัวตรวจต้องผสมสีตัวหนังสือกับพื้นตามค่า alpha ก่อนคำนวณ และต้องผสมพื้นโปร่งที่ซ้อนกันหลายชั้นด้วย
> (`.ci-label` อยู่บนการ์ดโปร่ง ที่วางบนพื้น `--accent2` อีกที)

## กฎที่ต้องรักษาไว้เสมอ

| กฎ | เหตุผล |
|---|---|
| **แก้ `style.css` หรือ `script.js` แล้วต้องเปลี่ยนเลข `?v=` ใน `index.html`** (ท้าย `<link>` และ `<script>`) ก่อนอัปขึ้น GitHub | เบราว์เซอร์จำไฟล์ CSS/JS เก่าไว้ แต่ HTML มักโหลดใหม่ ได้ของผสมที่ไม่เข้ากัน · เคยเกิดจริง: HTML ใหม่ใส่ `width/height` ให้รูปโปรไฟล์ แต่ CSS เก่าในแคชไม่มี `img { height: auto }` รูปจึงสูง 1433px ยืดเป็นเส้น · ใช้วันที่เป็นเลขรุ่นก็พอ เช่น `20260917` |
| ทุก `<img>` ต้องมี `alt` | คนใช้ screen reader และตอนรูปโหลดไม่ขึ้น |
| ทุก `target="_blank"` ต้องมี `rel="noopener noreferrer"` | ความปลอดภัย |
| path ต้องเป็น `images/...` `pdf/...` **ห้ามมี `../`** | ถ้าพลาดรูปจะแตกทั้งเว็บตอน deploy |
| **ชื่อไฟล์ในโฟลเดอร์ `images/` และ `pdf/` ต้องเป็นอังกฤษ ตัวเล็ก คั่นด้วย `-`** | ชื่อไทยพอเข้า URL กลายเป็น `%E0%B8%A3...` ยาว 60+ ตัว เคยหล่นหายตอนอัปขึ้น GitHub จนลิงก์ 404 มาแล้ว |
| ห้ามมีเว้นวรรคในชื่อไฟล์ | กลายเป็น `%20` ในลิงก์ พิมพ์ตามยาก และบางเครื่องมือตัดชื่อตรงช่องว่าง |
| ใส่คลาส `reveal` ถ้าอยากให้ค่อย ๆ ปรากฏตอนเลื่อน | เพิ่ม `reveal-delay` / `reveal-delay-2` เพื่อหน่วงเป็นลำดับ |
| section ใหม่ควรมี `id` และลิงก์ทั้งใน `.nav-links` และ `.mobile-menu` | ไม่งั้นเข้าไม่ถึงจากเมนู ต้องเลื่อนหาเอง (Workshop ตั้งใจไม่ใส่ เพราะเมนูจะยาวเกินไป) |
| `@media (max-width: ...)` ต้องเรียง **กว้างไปแคบ** เสมอ | specificity เท่ากัน ตัวที่อยู่ทีหลังชนะ ถ้าเรียงสลับ ค่าที่แคบกว่าจะไม่ทำงานเลย |

> ถ้าเพิ่มลิงก์เมนู ต้องขยาย `max-height` ของ `.mobile-menu.open` ใน [`../style.css`](../style.css) ด้วย (ตอนนี้ตั้งไว้สำหรับ 6 ลิงก์)
> (ลิงก์ละ ~58px — สูตรอยู่ในคอมเมนต์ตรงนั้น) ไม่งั้นลิงก์ท้าย ๆ จะโดน `overflow: hidden` ตัดหายและกดไม่ได้

- [ ] เปิดหน้าเว็บแล้วรูปขึ้นครบ ไม่มีไอคอนรูปแตก
- [ ] Console ไม่มี error
- [ ] ย่อจอเหลือ 375px แล้วไม่มี horizontal scroll · hamburger ทำงาน
- [ ] ลากหน้าต่างช่วง 960–1100px ดูว่าเมนู 6 ลิงก์ไม่ล้น (จุดคับสุดอยู่ที่ 961px กับ 1041px)
- [ ] ดูแถบ Logo Loop ครบหนึ่งรอบ (~30 วิ) ว่าไม่กระตุกและไม่มีช่องว่างโผล่ตอนวนกลับ
- [ ] ไทล์ทั้ง 28 ใบต้องเห็นโลโก้ครบ (ระวังโลโก้สีขาวล้วนที่จะหายไปบนพื้นขาว) และป้ายชื่ออยู่ระดับเดียวกันหมด
- [ ] แก้ CSS แล้วต้องกด Ctrl+Shift+R (hard reload) ก่อนตรวจ ไม่งั้นเบราว์เซอร์ยังใช้ไฟล์เก่าจากแคช
- [ ] ลากหน้าต่างจากกว้างไปแคบ ดูว่าขนาดไทล์ค่อย ๆ เปลี่ยน ไม่กระโดดกลับไปใหญ่ขึ้นตอนจอแคบลง
- [ ] กด Tab ไล่ทั้งหน้า เห็นกรอบโฟกัสทุกจุด
- [ ] คลิก "ดูเอกสาร" ทุกไฟล์ PDF เปิดได้ครบ
- [ ] เปิดกล่องรายละเอียด Workshop ครบ 4 ใบ · กด Esc ปิดได้ · กดฉากหลังปิดได้ · กดก่อนหน้า/ถัดไปวนครบวง
- [ ] ปิดกล่องแล้วหน้ากลับมาเลื่อนได้ และโฟกัสกลับไปอยู่ที่ปุ่มที่กดเปิด
- [ ] เอาเมาส์ชี้ปุ่มและชิปทุกแบบ ตัวหนังสือยังอ่านออก (สถานะ hover ตัวตรวจปกติมองไม่เห็น)
- [ ] ดูส่วน Contact กับ footer ซึ่งพื้นเป็นกรมท่า สีที่ใช้ได้บนพื้นสว่างมักใช้ไม่ได้ตรงนี้
- [ ] ใส่ URL เต็มใน `og:url` และ `og:image` แล้ว (Facebook/LINE ไม่รับ path สั้น)
- [ ] **ปิด JavaScript แล้วเปิดหน้าเว็บ ต้องยังอ่านเนื้อหาได้ครบ** — `.reveal` ตั้ง `opacity: 0` ไว้ ถ้า `<noscript>` ใน `<head>` หายไปเมื่อไหร่ หน้าจะว่างเปล่าทั้งหน้า
- [ ] เปิดหน้ามาเฉย ๆ ยังไม่เลื่อนจอ ต้องมีเมนูสักอันถูกไฮไลต์แล้ว
- [ ] มี `<h1>` อยู่ 1 ตัวเสมอ (ตอนนี้เป็น `.sr-only` ซ่อนไว้) และ `.section-label` ทั้ง 7 อันต้องเป็น `<h2>` ไม่ใช่ `<div>` · หัวข้อในการ์ดเป็น `<h3>` ห้ามข้ามไป `<h4>` (ข้ามลำดับแล้วโปรแกรมอ่านหน้าจอจะสรุปโครงหน้าผิด)

## งานที่อยากทำต่อ

- **ย่อรูปในโฟลเดอร์ `images/`** — รวมกันราว 6.5 MB (ใบรับรอง 6 ใบ ~620 KB/ใบ · `INET.jpg` 1.1 MB · `Zahira.jpg` 1.0 MB) ย่อแบบเดียวกับที่ทำกับรูปโปรไฟล์ได้ · ค้างอยู่ที่ว่าใบรับรองจะให้คลิกซูมได้ไหม ถ้าจะทำต้องเก็บตัวเต็มไว้ด้วย
- **Font Awesome เหลือใช้ไอคอนเดียว** — `fa-certificate` 6 จุด แต่ยังโหลด stylesheet ทั้งก้อนจาก CDN แบบ render-blocking ถ้าย้ายเป็น `<symbol>` ใน sprite จะตัด `<link>` ออกได้เลย
- **breakpoint กระจาย 5 ค่า** (1040 / 960 / 768 / 600 / 560) ควรรวบให้เหลือน้อยกว่านี้
- **CSS 16 rule ที่ยังไม่มีใครใช้** — ส่วนใหญ่มาร์กอัปถูกคอมเมนต์ทิ้งไว้ใน `index.html` (`.section-title` 6 รูปแบบ · `.proj-tag` + `:hover` · `.tag-blue` `.tag-green` `.tag-purple` · `.proj-year` · `.pc-header` · `.tl-highlights span` + `:hover` · `.about-text strong`) บวก **`.section-open`** ที่เพิ่งว่างลงตอนถอดออกจาก About · ยังไม่ลบเพราะถ้าเอามาร์กอัปกลับมาใช้จะได้ไม่ต้องเขียนใหม่ ถ้าแน่ใจว่าไม่ใช้แล้วค่อยลบทั้งคู่พร้อมกัน
  > **เวลาไล่หา rule ที่ไม่มีใครใช้ ระวังคลาสที่ JS เป็นคนใส่** — `.navbar.scrolled` `.mobile-menu.open` `#backToTop.show` `.reveal.visible` `.ripple-effect` `.contact-copy[hidden]` ไม่มีอยู่ใน HTML เลย แต่ทั้งหมดใช้งานอยู่จริง **ห้ามลบ**
